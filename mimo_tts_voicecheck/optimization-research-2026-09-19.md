# 八千代语音相似度优化 · 调研/诊断/方案评估（2026-09-19）

> 上游：`optimization-handoff-2026-09-19.md`（R1–R4 工作项 + H1–H3 假设）。
> 本报告 = 调研（两路子代理）+ 本席诊断实验 + 方案评估。**结论供拍板，未动生产链。**

## 0. 结论摘要（TL;DR）

1. **H1 量化坐实，是主瓶颈**：现役参考源 = 74kbps mp3，有效带宽仅 ~5kHz（99% 能量），12kHz 处 -94dB（数字无声级）。声线辨识所需的齿音/气声频段（5–15kHz）完全缺失——喂任何引擎都到顶。
2. **H2 部分坐实、待决性实验**：社区共识「微调 >> 零样本」；但 MiMo 配干净参考的上限还没测过（现有素材无一干净+宽频+单人，测不了）。
3. **两枚改变棋局的新事实**：
   - **本机有 RTX 4060 Ti 8GB**（交接简报未知）→ 微调路线本地闭环可行，无需租卡；
   - **官方闹钟 App『超かぐや姫！アラーム』2026-09-18 刚上线**（B 站演示视频的正主），免费 25 条 + 内购 30 条八千代新录干声 → 零成本换参考的第一杠杆。
4. **推荐分阶段走**（见 §5）：Stage 0 换 App 干声参考 → MiMo 复测（决定性实验）→ 不行再 BD 语料 + 本地微调双引擎 AB（GPT-SoVITS 主线 / SBV2 日语感对照）→ 商业 API 兜底。

## 1. 诊断结果

### 1.1 H1 参考源质量天花板 —— 坐实（本席取证，可复现）

工具：`spectral_check.py`（本目录，已固化；新素材到手后用它验收带宽）。

| 素材 | 码率/格式 | f95 | f99 | dB@10k | dB@12k |
|---|---|---|---|---|---|
| candidate_01（闹钟 App rip，**recutB 的源**） | 74kbps mp3 | 3.7k | **5.0k** | -41 | **-94** |
| candidate_03（闹钟下一段） | 88kbps mp3 | 3.4k | 5.0k | -45 | -94 |
| candidate_02（正片 BGM 版） | 104kbps mp3 | 3.4k | 6.4k | -37 | -41 |
| candidate_04（特典多人） | 165kbps mp3 | 1.9k | 9.4k | -36 | -41 |
| candidate_05（剪辑 BGM） | 170kbps mp3 | 3.4k | 8.6k | -29 | -32 |
| recutB（现役参考） | 24k wav 容器 | 3.7k | 5.1k | -42 | -89 |

判读：

- 干净单人素材（01/03）带宽全卡在 **5kHz**；频带宽的（04/05）都带 BGM/多人——当时横评是「干净度压过频宽」，不是源都不差。
- 干净 CD 级女声预期 f99 ≥ 9kHz、10kHz 处 > -35dB。差距是断崖级的。
- **附带发现**：MiMo 输出在 6–10kHz 能量反而比参考高（如 @6k：-16dB vs 参考的 -33dB）——引擎会自行外推「通用齿音」。所以缺的不是高频本身，而是**目标声线高频特征的身份证**：有损压缩给模型的是带伪影的声线画像，外推出来的齿音是「别人的」。
- R4 官方口径（mimo.mi.com 文档已核）：参考音频只说「数秒即可」+ mp3/wav + base64 ≤10MB，**无任何质量/带宽建议**；输出固定 24kHz/16bit/mono。即「更长参考」无官方背书，合成侧天花板本身也在 12kHz。

**先修正硬件账**：本机 = RTX 4060 Ti 8GB + 96G RAM（交接简报「无卡」假设作废）→ **本地训练+本地推理全链闭环，零现金成本**。

部署结论（关键问题 C 的回答）：

- **本地 4060Ti 常驻 API + frp 穿透给服务器 = 推荐路径**。服务器同机已有 frps，穿透零成本；AstrBot 已有 GPT-SoVITS 现成插件（Zhalslar/astrbot_plugin_GPT_SoVITS），只换「文本→wav」一节，投递层全复用。代价：本机需常开（关睡眠）。
- **服务器 CPU 推理不推荐**（2.7G 空闲内存 + 单句 10–40s 延迟，体验明显劣化）。
- **租卡只在两种情况**：本地被占用 / 要跑 DPO（AutoDL 4090 ¥1.88/时，一轮 <¥10）。
- 数据集制备：两引擎 WebUI 均自带（UVR5→切分→Faster-Whisper large-v3 日语转写→校对），10min 语料人工校对约 1–2h。
- 微调 vs 零样本提升幅度：无公开定量 SIM AB（UNVERIFIED），定性证据一致强（「GPT-SoVITS 零样本基本不可用，必须干声训练」等）。**数据质量与转写校对比数据量更影响观感。**

## 4. 方案评估（分阶段 + 决策门）

**Stage 0 · 零成本立即可做（本周）**
1. 用户试听 `outputs/ab_2026-09-19/`（H3 对 + 多段参考组）→ 判词回填本报告 §1.2/§1.3。
2. Android 手机装官方闹钟 App → 免费领 25 条八千代干声 →（内购酌情 +30 条）→ 取出原始音频文件 → `spectral_check.py` 验带宽 → 挑 10–20s 最贴耳一段替换 recutB → MiMo 复测三句。
   - **这是 H2 的决定性实验**：干净宽频参考 + 零样本。像了 → 全剧终，MiMo 免费链保住；不像 → H2 坐实，进 Stage 1/2。
3. YouTube 星降る海片段顺手按时间码预筛 BD 到货后的切片段（yt-dlp，AAC 比二压 mp3 干净）。

**Stage 1 · 语料到位（决策：买 BD，¥330 左右通常版即可起步）**
- 通常版 6,800 円含本篇（旁白线最干净）+ 5 条迎宾广播；要 31min 角色评论和特典 CD 才上特装版 16,800 円。提取 FLAC 后 `spectral_check.py` 验收（预期 f99 ≥ 9kHz）。
- 拿到语料先做**第二决定性实验**：MiMo + 10–20s BD 干净段参考复测——给零样本最后一次机会。

**Stage 2 · 微调双引擎 AB（若 Stage 0/1 复测仍不像；本机 4060Ti，0 元）**
- 同一份数据集两边训：GPT-SoVITS v2ProPlus（主线）+ SBV2 JP-Extra（日语感对照），各 1.5–3h。
- 接入：GPT-SoVITS api_v2 常驻 + frp → AstrBot 现成插件；SBV2 同构二选一。**此段是新引擎接入大改 → 按交接模式出任务包提示词交 dev-hub**（顺路清 §11 欠账），不在本线内直接实施。
- MiMo 保留兜底（免费、稳、链路通），新旧并行验证后切换。

**兜底 T2 · 商业 API（本地不能常开时）**
- 先白嫖豆包新客 2 万字试用克隆试听「像不像」；满意 = 138 元一次性（低频用量调用费≈0）；不满意看 MiniMax。注意商业 API 对「克隆真人声线」多一层账号 ToS 风险。

**版权口径**（全线适用）：开源引擎许可只覆盖代码不覆盖声音；克隆真人声线涉人格权。现状=私聊低频自用、不分发合成物，风险低；**任何情况下不公开分发合成音频、不商用**。

## 5. 未验证项（诚实清单）

1. MiMo + 干净宽频参考的零样本上限（Stage 0/2 决定性实验，未做）。
2. JP 女声「零样本 vs 微调」定量 SIM 差值（业界无公开 AB，仅定性共识）。
3. 闹钟 App 音频的实际格式/采样率（Android 到手验）。
4. BD 2ch 是否 LPCM（到手验；若 DD 有损则质量预期下调但仍远超 74kbps mp3）。
5. SBV2 在 4060Ti 的训练耗时（外推）；服务器 CPU 常驻内存精确值（不推荐路线，不再深挖）。
6. 豆包/MiniMax 对早見沙織系声线的具体还原度（只能试听）。
