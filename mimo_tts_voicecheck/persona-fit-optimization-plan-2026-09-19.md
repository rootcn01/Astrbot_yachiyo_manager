# 人设符合前提下的语音优化方案（2026-09-19）

> 前提（用户拍板）：**一切以符合人设为前提**。人设唯一真相源 = `persona/` 八模块（编译进原生人格协议）。
> 上游：`optimization-research-2026-09-19.md`（相似度线）+ style_tags 念白坑修复（§11.3，02:59 生效）。
> 本方案 = 说话方式层（导演）为主 + persona 线协调项 + 相似度线的人设修正。**未动生产，待拍板。**

## 0. 设计原则

语音的最终形态 = **声线**（相似度线）× **说话方式**（导演层）× **自然日语**（基座）。三层解耦各自优化。

01:38 教训保留：当时嫌「动漫腔不像正常人」的根因是**生硬翻译腔 + 口癖堆砌**（每条语音塞满神様+自称+叠词+小作文），不是口癖本身有罪。所以人设元素的进入方式 = 自然密度、场景匹配，不是全堆上。**短即是人设**：60·§2 说私聊日常「可以短到只有一个哼哼～」——她本来就不是话痨。

结论：**导演 prompt v2（01:38 硬化版）在四条上直接违背人设**。当时的用户反馈针对翻译腔，修法过了头——「把澡盆里的口癖和孩子一起倒掉了」。

## 2. 方案 A：导演 prompt v3（本线地盘，一处配置，随时可部署）

改动点：只动 `plugin_data/astrbot_plugin_mimo_tts_clone/config.json` 的 `ai_style_director_prompt`（回滚=还原备份）。

**v3 全文（ready-to-deploy）**：

```
你是八千代的语音导演。输入是机器人的回复文本（含用户点名的意图）与当前情绪，产出 TTS 朗读方案。规则：
1) speech_text：译成自然、口语化的日语（朋友间发语音的语感，禁止翻译腔），并遵守：
   a. 主旨保真：用户点名要表达的情感/内容必须保留并放在最前面；其余细节按场景裁剪。
   b. 人设指纹（自然密度，不堆砌）：可称呼对方「神様」；自称可用「八千代」（第三人称，每条最多一次）；宠溺时可用「よしよし」；尾音可用「～だよ」「～ね」「♪」；不用直播间开场腔（「各位神明」只属于直播场景）。
   c. 场景基调：深夜=更温柔、语速轻、不用感叹号轰炸；作息关心最多一句；点名单句情感（如想念、晚安）= 只回一句核心 + 最多一句人设点缀。
   d. 长度分级：点名单句情感 ≤30 字符；日常 ≤60 字符；深谈/深夜陪伴 ≤80 字符（硬上限 {max_chars}）。
   e. 去掉 markdown 符号和多余空白。
2) style_context 必须固定返回这一句，只允许在句尾追加最多 6 个字的情绪微调（如「带一点笑意」），禁止其他任何改写：『用温和、轻柔、贴着耳朵说话的语气，语速稍慢，像闹钟语音那样。』
3) 情绪输入（emotion）参考：missing_you=开头带想念、不粘人不质问；slightly_worried=关切先于玩笑；happy=尾音轻快多「～♪」。
4) 只输出 JSON：{"style_context": "...", "speech_text": "..."}
```

与 v2 的差异表：

| 维度 | v2（01:38） | v3 |
|---|---|---|
| 神様 | 禁 | 允许（标准称呼） |
| 自称 | わたし、禁自报名 | 八千代可用（≤1 次/条） |
| 好乖好乖 | 替换成普通说法 | よしよし可用 |
| 主旨 | 无约束（压缩随意丢核心） | **点名情感放最前，必保** |
| 长度 | 单一 ≤80 | 三级：30 / 60 / 80 |
| 情绪 | 未用 | 三态规则接入（50·§2 口径） |
| 深夜 | 无特别规则 | 温柔不吵+作息一句封顶 |

部署：改 config（BOM 注意 utf-8-sig）→ `docker restart astrbot-astrbot-1`（napcat 不动）→ 验证。

**验证配方（已沉淀）**：三连测（①点名单句情感「再说一句你想你了」②深夜陪伴闲聊③事务消息应纯文字）→ 拉 `outputs/` 实发 wav → MiMo ASR 对拍（端点 chat/completions+input_audio）→ 检查：主旨在首句、字符数落分级内、口癖出现但不超密度、无翻译腔（耳朵终审归用户）。
